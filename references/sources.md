## Research rules

1. Prefer the applicable specification or EIP for protocol-level claims.
2. Use official developer documentation for explanations and implementation guidance.
3. Check EIP status before describing a proposal as active or implemented.
4. Distinguish consensus rules from client-specific behavior and common practice.
5. Include relevant fork or version context where behavior changes over time.
6. Cite sources close to the claims they support; explain concepts in original wording.
7. Add a `Last reviewed` date for topics likely to change.
8. If sources disagree or status is uncertain, state that openly and record what needs verification.

External links can change. Confirm they remain relevant before marking an article reviewed.
